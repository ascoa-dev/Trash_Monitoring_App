# Agent notes — We Monitor (Flutter app)

Flutter app for ASCOA (`com.ascoa.wemonitor`), GetX + Firebase (project `trash-monitoring-app-88131`).
Full reference: `PROJECT_MASTER-ASCOA.md` (one level up, outside this repo). Store/release guide: `APPSTORE_PUBLISHING.md`.

Current version: **1.1.2** (`pubspec.yaml` 1.1.2+12). 1.1.0 is live on Google Play and the App Store.

## Releasing a new version — required steps

1. Bump `version:` in `pubspec.yaml` (and `build-script.ps1`, which is gitignored).
2. **Write the release notes** in all four `store_listings/*/*/changelog.md` files (see "Store listings" below).
3. Android: build the AAB locally and upload to Play Console (EN + FR notes, each ≤ 500 characters).
4. iOS: push to `main` → Xcode Cloud workflow **Default** archives and uploads to TestFlight. Submit the build in App Store Connect.
5. **When the new version is live in a store, update Firestore `config/app_version`.**
   Otherwise existing users never see the in-app "Update available" dialog
   (`lib/shared/services/update_service.dart` compares the installed version with this doc on launch).
   ```bash
   cd "../Firebase Functions/scripts"   # has firebase-admin installed
   node --input-type=module -e "import admin from 'firebase-admin'; admin.initializeApp({projectId:'trash-monitoring-app-88131'}); await admin.firestore().doc('config/app_version').set({android:{latest:'X.Y.Z'}, ios:{latest:'X.Y.Z'}}, {merge:true}); process.exit(0)"
   ```
   - `latest`: newest store version (dismissible prompt). `min`: oldest allowed version (forced prompt; raise only for breaking changes).
   - Update each platform only after its store shows the version. Needs `gcloud auth application-default login`.
6. Update the version header in `APPSTORE_PUBLISHING.md` and `PROJECT_MASTER-ASCOA.md` (§0, §13).

## Store listings

Everything uploaded to the stores lives in `store_listings/`, ready to copy and paste:

```
store_listings/
  icon_512.png, icon_1024.png            shared icons (Play icon / App Store reference)
  playstore/<en|fr>/
    short_description.txt                max 80 chars
    full_description.txt                 max 4000 chars
    changelog.md                         "What's new", max 500 chars
    feature_graphic.png                  1024x500
    screenshots/phone|tablet_7|tablet_10/
  appstore/app_info.md                   name, URLs, category (same for all languages)
  appstore/<en|fr>/
    subtitle.txt (max 30), promotional_text.txt (max 170), keywords.txt (max 100),
    description.txt (max 4000), changelog.md ("What's New")
    screenshots/iphone_6.9|ipad_13/
```

- EN and FR always match 1:1. Change one language, change the other.
- Screenshots and feature graphics are generated by `tool/screenshots/` (see its README). Don't hand-edit them.

### changelog.md: one version only

Each `changelog.md` holds **only the notes for the version being released**, so it can be pasted straight into the store.
When bumping the version:

1. **Delete everything already in the file** and write the new version's notes. No history, no headings, no version number.
2. Plain `•` bullets, written for users (what changed for them, not code details).
3. Write all four files: `playstore/en`, `playstore/fr`, `appstore/en`, `appstore/fr`. The Play and App Store text can be the same; keep Play ≤ 500 characters per language.
4. List the changes since the version currently live in the stores, not just since the last commit.

## Conventions

- All user-facing strings are translated: add keys to both EN and FR maps in `lib/shared/i18n/strings_*.dart`.
- Hive adapters (`*.g.dart`) are edited by hand when `build_runner` can't resolve; keep field numbers unique.
- Never commit `build-script.ps1`, `android/key.properties`, `android/app/key.jks` or `.env`.
- `ios/ci_scripts/*.sh` must keep LF line endings (enforced by `.gitattributes`).
- Run `flutter analyze` and `flutter test` before pushing.
